## Test Cases

### TC-01: Child Login (happy path)
- Preconditions: Frontend running at http://localhost:3000, user exists.
- Steps:
  1. Go to /login.
  2. Enter child email and password.
  3. Click submit.
- Expected:
  - User is authenticated and redirected to the game launch or dashboard.
  - Session contains role = "child".
  - Session persists after refresh.

### TC-02: Parent Login and create child
- Preconditions: Frontend running, parent account exists.
- Steps:
  1. Login as parent.
  2. Navigate to parent dashboard.
  3. Create a child account with display name and credentials.
- Expected:
  - Child record created and linked to parent_id.
  - Parent can view child in dashboard.

### TC-03: Start game and problem presentation
- Preconditions: Child logged in, on game start screen.
- Steps:
  1. Click Start Game.
  2. Observe problem card.
- Expected:
  - Problem displays flavor_text and problem stem.
  - Input for numeric answer is visible.

### TC-04: Correct answer handling
- Preconditions: Problem shown.
- Steps:
  1. Submit a correct answer.
- Expected:
  - Coins awarded according to speed/attempts.
  - Next problem presented.
  - No correct answer value present in DOM or network responses.

### TC-05: Incorrect answer handling
- Preconditions: Problem shown.
- Steps:
  1. Submit an incorrect answer.
- Expected:
  - Problem is restated; no health reduction or punitive animation.
  - After 3 consecutive wrong answers, a 10s cooldown is enforced.
  - Rate-limit of 1 attempt per 3s enforced.

### TC-06: Coin balance updates and persistence
- Preconditions: Child logged in.
- Steps:
  1. Answer correctly multiple times.
  2. Observe coin balance.
  3. Refresh the browser.
- Expected:
  - Coin balance updates immediately and persists after refresh.
  - Coin cap rules enforced (daily cap 300).

### TC-07: Streak bonuses
- Preconditions: Child logged in.
- Steps:
  1. Answer consecutively to build streaks (3, 5, 10).
- Expected:
  - Streak bonuses applied and visible.
  - Streak resets on incorrect answer.

### TC-08: Timer and session limits
- Preconditions: Child logged in.
- Steps:
  1. Play until near session/daily limit.
- Expected:
  - Soft warning at 80% of limit.
  - Hard save-and-exit at 100%.

### Negative & Edge Cases
- Empty submission -> server validation error, no attempt recorded.
- Non-numeric submission -> rejected.
- Rapid repeated submissions -> rate limited.
- Very large numbers, negatives -> validated appropriately.
